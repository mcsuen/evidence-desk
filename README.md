# PITR

PITR 是面向公司与产业研究的本机工作站。它将研究问题、原始材料、数值、计算、判断和报告组织成可追溯、可持续修订的研究记录，提供网页阅读与可编辑的原生 Word 报告。

研究与独立复核通过本机已登录的 Codex 或 Claude Code 执行。PITR 负责保存证据、约束研究范围、管理版本与人工决定，将结论与其依据、适用条件一并保存。

## 为什么做 PITR

公司研究会随着财报披露、材料更正和假设变化不断延续。一份结论能否继续使用，取决于当时有哪些可得资料、数字采用什么口径、推断依赖哪些前提，以及这些前提是否已经改变。这些信息需要和结论一起保存。

因此，PITR 把证据、计算与判断之间的依赖纳入研究记录。阅读者可以从报告回到原件，研究者可以沿着变化找到需要重做的部分，后续研究可以复用仍然适用的成果。报告、公司知识和产业关系图都从同一组版本对象生成，使不同入口对同一事实保持一致。

## 工作台提供什么

| 研究环节 | 对应能力 |
| --- | --- |
| 提出问题 | 选择主体、期间与材料，使用问题界定、原件读取、财报变化、公司与产业尽调、估值等方法包组织研究 |
| 跟踪执行 | 通过运行图、瀑布时间线和节点详情查看工具调用、结果与失败位置；保留检查点，支持取消与继续 |
| 阅读与核对 | 分条阅读结论，点击已关联的行内数字查看原件摘录、期间、单位和计算依据；按需打开 PDF 页与来源全文 |
| 修订与交付 | 编辑章节、选择数值和引用，比较报告版本，导出包含原生表格与可编辑图表的 Word |
| 积累与更新 | 在公司页阅读知识、数据、判断、模型与产业关系，在今日页查看变化，在审核页决定采纳哪些判断 |
| 从资讯进入研究 | 在资讯实验室采集、评分和反馈新闻，结合公司上下文，将原件与问题提交为研究草稿 |

## 设计选择

### 数字携带口径，引用指向原件版本

同一个数值只有在主体、期间、单位和会计口径明确时才有比较意义。PITR 分别保存来源陈述、原文定位、解析后的数值和计算依赖；计算引用具体版本的输入，保留原文字面值及换算依据。季度与累计、实际与预测、ADS 与普通股等区别进入数值约束。

这些关联直接用于报告阅读：点击数字即可查看依据，同一原件的引用集中呈现，原文侧栏保留上下文。仅能定位原文的数字会明确标为原文定位；数值解析与口径检查另有记录，避免把一个可点击的链接误解为已经完成核验。

### 研究固定时点，变化产生新修订

每次执行固定问题、输入修订和允许使用的资料集合。历史研究同时约束资料的可得时间；资料上的发布日期需要相应的可得依据，后来的材料不能被当作当时已知的信息。

原件、判断、模型和报告以不可变修订保存。来源更正或撤回时，系统沿实际依赖标出受影响的结果，另行展示当前有效性；历史正文、当时的检查记录和已交付文件保持原样。继续研究形成新修订，使“当时据何判断”和“现在是否仍成立”都可以被查明。

### 检查、复核与人工采纳各自承担职责

确定性检查处理数值解析、计算、范围和引用等可明确判定的规则。核心判断、因果关系、估值假设与材料冲突交由独立会话复核，保存针对具体版本的意见。未执行、不可用、错误、不适用和通过分别表达，运行完成本身不代表结论可靠。

人工采纳绑定准确的判断版本。独立判断可以分别决定；相互依赖的判断作为一组采纳，避免只接收结论却遗漏其前提。来源身份用于理解材料出处，判断成熟度还需要结合证据与推理。资讯评分用于安排阅读优先级，进入正式研究后仍需建立相应的证据和判断记录。

### 网页和 Word 共用一份报告内容

报告由章节、段落、数值片段、引用、表格和图表组成。网页与 Word 都读取这份结构化内容，让正文数字、图表数据和引用保持相同的依赖关系，也让报告编辑可以重新检查受影响的内容。

每次导出固定报告与检查版本，保存文件摘要和生成记录。导出有独立队列，失败可单独重试，无需重新研究。Word 的正文、表格与常用图表可继续编辑；站外修改目前不回传站内，站内修订与已交付文件各自保留明确版本。

### Agent 通过受控工具提交结果

Agent 通过受控工具服务获取材料、读取对象和提交结果。服务端核对研究范围、输入版本、执行代次、租约与命令标识，确保取消后的调用、旧输入提交和重复请求不能错误改变正式记录。宿主隔离限制 Agent 直接访问业务数据与其他任务。

方法包按任务加载，版本与选择理由随执行保存。研究预算预留收尾空间，额度耗尽时保存部分成果与检查点，允许用户显式继续。这使长时间研究中的中断、恢复和资料变化都有清楚的处理边界。

## 本机架构

[![PITR 当前架构：统一应用命令、隔离的研究宿主、受控工具、版本存储与共享报告交付](docs/architecture.svg)](docs/architecture.svg)

研究队列把固定上下文交给隔离的 Agent；Agent 经受控工具读取证据、提交数值与判断。应用服务保存版本和人工决定，网页报告与 Word 导出读取同一个 ReportDocument。完整模块职责与读写边界见 [架构说明](docs/architecture.md)，图的可编辑源文件见 [architecture.mmd](docs/architecture.mmd)。

PITR 使用 Python / FastAPI、SQLite、文件对象存储和 React。原件与产物保存在本机，数据库记录对象版本、依赖和人工决定；公司知识、关系图与检索是可重建的派生视图。备份同时保留数据与原件，恢复历史报告和文件无需再次调用模型。

业务按领域规则、应用命令、研究调度、方法包、产物生成和外部接入分工。网页、薄 CLI 与 Slack 通过同一组业务命令工作，共用范围和版本约束。Pydantic 契约生成接口 Schema 与前端类型，使不同入口遵循相同的数据定义。

本机保存让研究记录、文件与备份由使用者掌握。模型调用仍通过所选宿主连接相应服务，来源获取也需要网络；资讯实验室可另行配置本地模型。

## 开始使用

一键启动支持 macOS Apple Silicon / Intel。安装并登录 Codex 或 Claude Code 后，在项目目录运行：

```sh
./start
```

首次启动需要网络，启动器准备项目私有运行环境并打开浏览器。研究数据默认保存在 `data/research`。

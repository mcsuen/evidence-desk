# Lab 新闻雷达

新闻雷达把公开报道与已有公司认识相联系，供研究员决定阅读顺序。入口位于侧栏的 Lab、命令面板，以及窄屏底部的“更多”。它使用独立的本地队列与 Laya 进程，采集和评分不会启动研究 Agent。

## 开始使用

1. 打开 Lab → 来源与运行，安装本地模型。安装使用独立环境，不更改工作台的 Python 依赖；需要首次联网下载。
2. 检查预置的中新网财经、DW 经济、美联储、欧洲央行订阅，以及已有观察名单中的公司公告。可添加 RSS／Atom 和交易所公告渠道。GDELT 默认关闭，启用时只发送填写的公开关键词。
3. 勾选自动采集并保存。默认间隔 30 分钟、每日最多 1,000 篇；取消勾选暂停自动调度，正在执行的批次完成后停止。也可点击“立即采集”。
4. 在新闻页切换精选、待确认、全部；“全部”支持低分抽查。公司范围默认为全部覆盖公司，筛选值只进入当前 URL，不改变其他页面记住的公司。

订阅是实际覆盖范围，不代表全球新闻全集。来源页记录获取错误、处理数量和额度限制。系统休眠期间不能采集，恢复后合并漏跑批次；未取得正文的地址会保留并重试，即使地址已经离开订阅列表。来源未公开、已撤下或订阅历史之外的内容可能无法补齐。

## 阅读与评分

关注分采用 `30% 公司相关性 + 30% 业务重要性 + 25% 研究影响 + 10% 信息增量 + 5% 时效性`。前三项来自 Laya 的二元判断分值；信息增量是同事件前后报道的文本差异，时效按发布时间衰减。它们不是财务预测或经过校准的投资概率。

当前门槛为关注分 ≥60、相关性 ≥0.5，且没有待核对事项。每天／当前最近 24 小时的精选最多展示 20 个事件。缺少正文、缺少可用公司条目、同名实体、推理失败、发布时间未知、模型置信度低等情况进入待确认。所有报道仍可从“全部”查阅。

候选公司通过登记的名称与别名、本地多语言语义检索召回。公司上下文固定已采纳的知识版本、产业关系、活跃论点、假设与开放问题，不采用未审核候选。当前保留最相关的三家公司及所有直接命中公司，每家公司判断最多三个“新闻片段 × 研究条目”。长文分段包含尾部；正文超过 100,000 字符时明确标记截取范围并保留完整原件。

每次评分保存公司上下文快照、片段位置、实际模型输入、原始输出、权重版本和模型身份。总分与模型置信度分开呈现。打开详情后 URL 固定评分 ID；重新评分只出现更新提示，点击后才切换。不同来源和后续报道保留原文，矛盾说法不会被合成为一份“共识摘要”。

聚合先比较规范化网址与原件摘要，再比较近期标题的本地语义向量。已识别公司不相交或发布时间相距超过三天的报道不会仅凭语义相似度合并。聚合与召回仍属实验方法；可以反馈不相关、重复、值得关注或提高优先级，原始分数保留用于评估。

## 转入研究

“深入研究”先保存服务端 `NewsResearchDraft`，再打开预填研究表单；URL 只传草稿 ID。表单可移除新闻原件和 Wiki 引用，补充上传附件或修改问题。已收录材料与新附件合计最多十份，上传失败重试不重复提交。

只有研究员提交表单后才进入现有 Agent 流程。原件按真实网址及发布身份进入资料系统，不把媒体报道提升为公司官方资料。新闻评分不是已采纳知识。原有历史截止、材料可得性、Wiki 版本、研究范围及审核校验继续生效；服务端覆盖客户端提交的评分来源，保留真实草稿、评分和上下文身份。

## 本地部署与运维

固定版本：

| 组件 | 版本 |
| --- | --- |
| Laya SDK | `573e5b62696ba441230cd6be71d593331b5d23af` |
| Laya 多语言模型 | `convaiinnovations/laya`，`1c5edc17a7acd8701df6fc341c0d179f1c62c982`，`multilingual/` |
| 多语言语义模型 | `intfloat/multilingual-e5-small`，`614241f622f53c4eeff9890bdc4f31cfecc418b3` |
| 评分策略 | `news-priority.1` |

安装器位于 `services/laya/install.py`，逐文件记录 SHA-256。默认环境为 `.pitr/laya/`，可用 `PITR_LAYA_HOME` 指定其他目录。进程启动时校验模型文件；日常推理开启离线模式。Laya 优先使用 Mac GPU，无法使用时由 SDK 回退 CPU，页面展示实际设备。语义编码使用 CPU，限制线程和批量，避免占满研究工作台资源。

```sh
uv run python -m pitr.lab.news --data-dir data/research install
uv run python -m pitr.lab.news --data-dir data/research collect
uv run python -m pitr.lab.news --data-dir data/research rescore
uv run python -m pitr.lab.news --data-dir data/research status
```

常驻工作台随启动运行 Lab worker；命令行一次性处理持久队列并退出。队列使用可续期租约，同一数据目录只执行一个新闻批次；重复点击合并在途工作，重启恢复未完成任务。每轮会对最近七天的报道检查公司上下文更新，并追加新的评分版本。

Lab 数据位于 `data/research/lab/news/`：`news.sqlite` 保存来源、事件、公司上下文、评分、反馈、草稿及队列，`originals/` 保存不可变原件。备份必须包含整个目录及工作台资料库；维护页完整备份包含 Lab 与主库资料，恢复会核对摘要和引用。模型环境可按固定版本重装，安装日志和推理日志保存在 `.pitr/laya/`。

接口统一位于 `/api/v1/lab/news/`：`settings`、`status`、`runs`、`events`、事件详情、事件反馈、研究草稿、草稿查询和原件读取。写请求沿用本机会话与 CSRF 校验，禁止 Agent 身份写入实验决策。Python 契约经 JSON Schema 生成 TypeScript。

## 验证与效果评估

自动测试覆盖去重与修订、矛盾报道保留、公司同名、长文尾部召回、失败补采、租约恢复、固定评分、前 20 上限、草稿幂等与来源身份、旧 Wiki 引用、历史截止及材料上限。浏览器检查桌面／390px、主题与密度、命令面板、URL 范围、前进后退、原文抽屉和焦点恢复。

容量回放使用合成新闻和真实本地模型，隔离于业务数据。可以读取当前公司上下文，但不会向该资料库写入合成新闻：

```sh
uv run python scripts/benchmark_news.py --count 1000 \
  --profiles-from data/research --output .pitr/news-capacity-new
```

使用新的输出目录以避免复用上次评分。报告包括吞吐、积压、进程 RSS、MPS 驱动分配和同时读取公司／提交研究的耗时。RSS 与 MPS 分配不能简单相加为物理内存；回放不包含公网延迟，研究理解步骤使用明确的离线测试解释，不调用外部 Agent。容量结果不能证明真实新闻筛选质量。

2026-09-23 的 M4／16 GB 实测见[容量报告](benchmarks/news-m4-2026-09-23.json)：读取 7 家公司、4 个可用研究条目，1,000 篇合成报道使用真实本地推理耗时 796 秒；未处理报道为 0。生成 1,000 条数值评分及 1,500 条等待补充公司上下文的记录，后者属于待确认而不是执行积压。进程 RSS 峰值约 2.31 GiB、MPS 驱动分配约 2.36 GiB；同时提交研究进入队列耗时约 12.5 毫秒。

真实页面试读发现了推荐栏混入正文的问题，已修正正文提取、重新解析保存的原件，并保留旧评分版本。修正后仍观察到部分公司关联较弱的报道获得高分，所以当前精选只能作为待验证的实验排序，尚未证明有用率与召回率达标。

至少需要 200 个代表性人工标注事件才能评估效果。在详情中反馈是否值得关注，并展开“标注重要性”判断是否属于必须留意的事件。导出包括低分和未匹配事件，已有人工反馈会预填相应字段；人工补齐 `useful`、`important` 和 `annotator` 后再评估：

```sh
uv run python -m pitr.lab.news export-labels --file .pitr/news-labels.jsonl
uv run python -m pitr.lab.news evaluate --file .pitr/news-labels.jsonl
```

同一事件与公司不跨版本重复计数，精选按事件去重，并与公司关键词基线比较。目标是精选有用率 ≥70%、重要事件进入精选或待确认的召回率 ≥90%；需至少 20 个精选判断、200 个独立事件及实际重要样本。报告同时列出待确认负担和基线召回，避免只靠把大量新闻放入待确认就误判效果。

调参后的效果应在新的事件样本上复验，不能把同事件的另一篇报道当作独立验证集。未有足够人工样本时页面显示“尚待验证”，未达标显示“未达目标”；即使本批评估达标，模型置信度仍标为未校准。

## 最终内核接入

公司背景来自统一 Subject 与已采纳知识的准确修订。新闻原件进入不可变 SourceVersion；研究草稿包含原件引用与固定公司背景。新闻评分、反馈、本地 Laya / E5 能力保留，评分不会转化成研究核验或自动采纳。

上文旧工作区数字是此前资讯实验记录，不代表本次重构的整体验收。新契约下的专项、浏览器与全量结果以 [本次验收](acceptance.md) 为准。

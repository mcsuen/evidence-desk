# Slack 接入

设置页配置 Socket Mode 的 App Token、Bot Token、允许的 workspace、owner 与频道，然后显式启用。默认不连接，不会主动向任何人发送研究。

渠道命令与网页共用新内核：

- `new PDD 研究问题`：将附件保存为不可变原件，创建输入并启动研究。
- `status RUN_ID`：查看执行进度。
- `cancel RUN_ID`：取消并保留检查点。
- `continue RUN_ID`：显式增加预算、继续同一执行。
- `export RUN_ID`：为准确报告版本排入独立 Word 队列。
- `help`：显示命令帮助。

Slash command 为 `/research`；私聊、mention 和既有线程按通用渠道规则分派到研究工作流。主体须先在工作站登记。报告采纳与站内修订使用工作台，避免从含糊的聊天指令自动采纳。

Socket Mode 先将事件持久入队，再向 Slack 确认接收，随后执行研究。输入事件 ID 用作业务操作标识，附件按摘要保存；工作流不获得 Slack SDK 或任意文件路径。渠道白名单、附件下载域名、大小、错误重试和会话绑定继续使用已有传输边界。修改/删除历史消息不会覆盖已经冻结的研究输入。

导出后从文件对象读取同一份 DOCX 交付，不在渠道重新生成报告。投递失败重试由渠道日志管理，业务研究不重跑。恢复备份会保留日志，但暂停待投递与旧绑定；不会因恢复自动重复发送。需要所有者在真实渠道查看情况后发起新的命令。

本次工程验收通过离线 Socket Mode 请求监听器和新 ResearchWorkflow 测试；未向真实 Slack 发消息，也不声明完成外部 workspace 的真人验收。

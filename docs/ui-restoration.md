# 成熟界面恢复与验收

本次将重构前最近一版 React 界面、设计规范、React Flow / ELK 运行图及瀑布图接入 E 内核。生产入口仍是 `/api/v1` 和 `data/research`。没有恢复旧业务控制层、旧数据库、旧 HTML 报告或兼容投影；资讯实验室、站内报告修订、独立复核与原生 Word 保留。

此前 A—E 的业务验收没有覆盖重构前后的视觉对照，导致界面退化。本次以 `tmp/implementation-baseline/before.zip` 中的完整 React 源码为参照；恢复前的新内核工作区另存于 `tmp/ui-restoration-baseline/before.zip`。这两个本地备份均未被覆盖。

## 真实记录与准确版本

- 执行记录补齐 Agent、工具、独立复核、导出尝试的开始/结束、父子、代次和输入版本。被取消、过期或重复的调用不会因留下 Trace 而获得正式写入权限。
- 历史回放按事件位置投影，不借用未来结果或耗时。旧 E 执行没有采集的开始时间、时长和 token 显示“未采集”，不补造流程。
- 图形结构和节点详情分别读取；订阅只推送轻量变化通知，断线按游标恢复。输入输出、原件和宿主事件在选择节点后加载。
- 公司页面由版本对象与人工决定派生；历史时点、主体范围和来源可得性复用内核规则。关系成熟度来自判断语义，来源身份标签不改变采纳资格。正文旁的当前有效性提示不改写旧正文。
- 公司数值表显示原始 Decimal 字符串；图表按单位、口径、频率、币种、股数基础和数据角色分组。图形坐标使用浏览器数值，但阅读和证据仍保留准确值。

## 验收方法

旧 React 参照和恢复后的系统分别使用独立临时数据、端口与明确标注的离线材料。浏览器夹具还会复制当前构建产物，避免同时构建或启动项目时清空测试正在读取的页面文件。没有向默认业务库灌入演示数据。旧夹具的部分公司页面为空，因此对照的是布局、视觉体系和交互；新关系与知识用新内核创建的离线判断验收，没有转换旧事实。

18 个主要页面各检查浅色/深色、1440 × 1000 桌面和 390 × 844 窄屏，共 72 个视口截图。包括今日、研究输入、报告、运行图、瀑布、公司列表及八个公司子页、审核、维护、设置、资讯。参考与恢复截图保存在本地 `output/ui-restoration`；可重复的截图基线纳入 `web/restoration-tests`。截图比较允许少量时间文字差异，另检查浏览器异常、页面横向溢出和误用旧接口。

界面检查发现并修复了流程连线被通用 SVG 样式压缩、首次公司选择竞态、附件列表刷新、设置轮询覆盖未保存输入、历史时间输入格式、窄屏表格溢出和页头挤压等问题。对照检查包含节点详情、证据阅读、关系点击、历史查看和手机焦点恢复，不以“页面能加载”代替交互验证。

保留原有 6 条 E 浏览器路径：研究取消/继续、版本与 Word 独立重试、资讯转研究、审核及派生页、手机证据、来源更正后的判断修订。另有 10 项界面与截图验收，以及 Trace/公司投影、订阅恢复、导出重试、大事件内容存储的后端反例。最终后端 235 项通过，Pydantic / TypeScript 的 84 个契约模块核对通过，前端生产构建通过；两套浏览器共 16 项通过，72 张截图基线复测通过。

Codex、Claude 均使用真实本机宿主重新验证受控调用后取消、服务重启、预算耗尽后的部分报告、显式继续和独立复核。最终均在第 3 代完成，两项检查通过；记录能重建父子调用和恢复连线。该冒烟使用明确标注的小型示例原件，不冒充新的 PDD 研究效果评测。

机器可读结果、测试数量和源码摘要见 [ui-restoration-acceptance.json](benchmarks/ui-restoration-acceptance.json)。原有 PDD、Word 逐页渲染与全新安装验收保留在 [A—E 验收记录](acceptance.md)，本次没有重写其历史记录。

## 复现

```sh
uv run python -m pitr.schemas --check
npm --prefix web run check-types
npm --prefix web run build
uv run pytest -q
npm --prefix web test
npm --prefix web run test:ui
```

界面套件默认使用端口 18885，可通过 `PITR_RESTORATION_PORT` 调整。截图基线更新应先完成目视对照，再运行 `npm --prefix web run test:ui -- --update-snapshots`。研究、图形、PDF 和图表继续按需加载；以后替换领域模型时应保留有价值的展示组件，并同时执行业务和界面回归。

本次实际浏览器环境是 macOS 上的 Chrome，窄屏由浏览器视口模拟；不声称已在真机 Safari、Android 或其他操作系统完成验收。人工研究效果盲评仍是交付后的评估，不由这些工程检查代替。

## 报告阅读恢复补充（2026-09-24）

按原 React 报告的分条结论、行内数字入口和原文侧栏恢复阅读体验。正文不再插入成串的方括号编号；同一段落和表格单元格的引用按准确的原件版本合并为来源入口，多份来源可完整展开。报告版本选择保持简短，完整修改原因放在“本版修改说明”中。

类型化数值仍直接引用 Value，展示原文、期间、口径和计算依赖。仅有文字与引文的历史报告允许一种明确标注的“原文定位”：数字必须与本段紧邻引用或表格同行引用中的完整字面值唯一对应；不做四舍五入、单位换算、跨段搜索或歧义选取，也不创建数值对象或提升核验资格。原文摘录高亮所点数字，支持前后文、PDF 页预览和准确版本的原件链接。来源撤回单独提示；切换报告版本关闭原版本的依据。报告正文和已导出文件没有被改写。

补充的报告阅读夹具覆盖密集引用、同名原件的不同修订、负数、歧义数值、原文 Unicode 定位、来源撤回及手机焦点返回。新增 7 项测试（2 项纯逻辑、5 项浏览器）和 8 张深浅色/桌面/窄屏截图；原有 10 项界面验收和 6 项 E 产品路径继续执行，后者包括报告修订、版本切换和 Word 独立重试。截图库合计 80 张，只有报告相关的既有 4 张基线需要更新。结果记录在本地 `output/report-reading`，实际 Chrome 中另外检查了 Kimi / 智谱报告的数字定位和公告 PDF 原页。
